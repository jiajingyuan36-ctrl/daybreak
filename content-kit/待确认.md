# 待确认

> 做的过程中遇到需要 Leo 拍板的事，都记在这里。每一条都写了**我先采用的默认做法**，已经照着做了；你改主意的话告诉我，我再改。
> 按重要程度排序，前三条建议今晚就定。

## 今晚建议先定

### 1. 付费“深度解读”要不要继续挂在网站上？
- **情况**：网站 `/deep/` 写着“付费 · 一对一”，联系方式是微信；`src/site.ts` 写着经营者是高中生。网信办 2023 年专项行动原文点名“提供塔罗……等付费算命问答服务”；平台规则把“算塔罗/星座”类服务推广列为违规；未成年人对外有偿提供服务还涉及监护人同意（详见 01-研究 第二、五节）。
- **默认做法**：小红书帖子里**完全不提**深度解读、微信号和付费；**网站代码没有动**。
- **请你决定**：A. 先把 `/deep/` 改成“暂不开放”（我建议）；B. 和监护人商量后保留；C. 保持现状。

### 2. 小红书账号以谁的身份说话？
- **默认做法**：初稿用第一人称“我”，但不透露年龄和身份（例如 02 号“我起床后的第一件事”）。
- **请你决定**：“我”= Leo 本人 / “晨启”= 品牌 / 一个虚构角色；露不露脸、手、声音。

### 3. 帖子里怎么引到网站？
- **情况**：小红书对正文里的外链和站外导流有限制（具体尺度没查到原文，见 01-研究 第六节）。
- **默认做法**：正文**不写网址**，网站入口只放主页简介；配图里可以放网站截图，但不露网址。初稿正文最后没有“去我主页”之类的话。
- **请你决定**：要不要在正文加一句“想自己抽一张，可以看我主页”。

## 品牌与内容

4. **目标用户的年龄**：默认画像是 23 岁刚工作的女生（02-品牌文档草稿）。但网站里“学业”出现很多，你自己也是高中生——用户可能更年轻。这会影响话题标签（#打工人 还是 #学生党）和选题（考试周）。
5. **品牌一句话定位**：默认“晨启是你每天早上的第一个小仪式——亲手抽一张 1909 年的原版塔罗，读一句大白话，做一件十分钟的小事。”
6. **称呼**：默认用“你”，不用“宝子们 / 姐妹们”。
7. **固定结尾句**：默认每条结尾“塔罗只是给今天一个提醒，不预测未来。”
8. **发布时间**：默认周一、三、五早上 7:30。请用白羊座那条的数据核对一下哪个时段的曝光更好。
9. **系列顺序**：星座系列默认按“当季优先”而不是黄道顺序（白羊 → 天蝎 → 金牛 → 射手）。如果你想按黄道顺序一个个讲，第 2 期应该是金牛。
10. **02 号帖子“今天抽到节制”**：只是示例，发之前请换成你当天真实抽到的牌。
11. **06 号标题**：原想用“你的三张牌”，但实际是 5 张，默认改成“射手季要来了：你在塔罗里的牌”。
12. **账号名和简介**：默认建议名称“晨启塔罗 · 每天早上一张牌”，简介“1909 原版韦特塔罗 / 每天一个小提醒 / 不预测未来”。名称和简介里不要出现“算命”“改运”“大师”（2026 年账号名称专项治理）。

## 网站与代码

13. **分支基线**：PR #2（上一轮已上线的抽牌页改动）还没合并进 `main`。默认 `content-kit` 分支从 `claude/ritual-graphite-metal` 开出，和线上一致。建议先合并 PR #2，再合并 content-kit。
14. **这次的网站改动没有部署**（按你的要求）。要上线的话，需要重新打包并更新部署仓库，你说一声我来做。
15. **链接预览图**：现在所有页面共用一张 `/og.png`（1200×630）。默认没有为每页做单独的预览图；如果你想让星座页转发时显示星座图，可以再加。
16. **网站内的分享图要不要加 3:4？** 现在抽牌后能导出 4:5 和 9:16。默认这次只做了**批量封面脚本**，没改网站里的分享按钮。如果你希望用户自己抽完就能导出小红书尺寸，我可以加一个选项。
17. **Playwright**：封面脚本需要它，但我**没有写进 package.json**（避免线上 `npm ci` 多装一个浏览器）。你在自己电脑上第一次用时要装一下（README 里有命令）。
18. **小红书带来了多少人**：网站没有统计脚本，`src/lib/visit.ts` 只在访客自己的浏览器里记来源，**你看不到**。默认不加任何统计（和隐私说明一致）。如果想知道引流效果，可以考虑：在简介里放带参数的链接（例如 `?from=xhs`）+ 一个不记录个人信息的计数服务——这会改变隐私说明，需要你决定。
19. **首屏还能更快**：首页最大内容要等日历和月相算完才显示（模拟 4G + 手机 CPU 约 2.75 秒）。再快需要把当天的日历在构建时预先算好、按天重新部署，改动比较大，默认没做。

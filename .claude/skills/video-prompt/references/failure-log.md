# 踩坑记录与规则的证据范围

本项目最常犯的错：**把一个案例推成通用规则**，然后被下一个案例推翻。每条规则都写上「证据」和「适用范围」；只有一个案例支持的，标「单例」。

| 规则 | 证据 | 适用范围 / 反例 |
|---|---|---|
| 不写具体的负面表现（不要大哭、不要皱眉） | 面部特写 v1：列了一堆哭的表现，结果全做了 | 单例。**只管质量的负面限制可以写**（Gemini 西藏写了一串「严禁磨皮、HDR……」，没出问题） |
| 不写品牌、型号 | 泰坦尼克 09：车钟表盘上印出 KODAK Vision3 500T | 单例。**只在画面里有能写字的表面时有风险**（Gemini 西藏写了 ARRI Alexa 65，没出问题） |
| 特征写太细会被字面化 | 珠峰第一轮：写了「黄带」「斜向冰沟」，山上被画出条纹 | 单例。适用于地形、建筑这类结构特征 |
| 引号里的字会被念出来 | 多次 | 多例。要台词就用引号，不要就别用 |
| 推近会被放大 | 珠峰 B、D；西藏 A-4 | 多例（Muse） |
| 定妆照起步能保一致 | 珠峰 B/D/E/K、泰坦尼克 18 个镜头 | 多例（Muse） |
| Muse 会中途切镜 | 泰坦尼克 02、03、17 | 多例。交回后要检测 |
| Muse 只出 720p，有时 3:2 | 所有素材；泰坦尼克第一批 | 多例 |
| 「越详细越好」 | 西藏 A-4 失败 | **错误规则**：详细本身不是问题，问题是光和运镜没设计好（Gemini 详细版成功） |
| 「默认一句话让 Muse 发挥」 | 用户的判断加第三方指南 | **未验证，被 Gemini 长提示词的成功挑战**。OpenAI 官方说两种都对，按目标选。需要同一场景的对照测试 |
| 「少即是真」（平光 + 跟拍） | 西藏第二版 | 真了，但丢了用户要的光影。**真实 ≠ 平淡** |
| 「精致」= 一眼 AI：金色光、史诗、电影感、饱和色把画面推向训练数据的平均画风 | 本项目多部片子；Prompt Architects、NovoAds、invideo 的分析 | 多例 + 多个来源。对策见 realism.md「精致本身就是破绽」。亚丁是第一次按这套写，结果待验 |
| 中文提示词对 Muse 更好 | Gemini 西藏是中文 | 未验证，没有对照 |

## 怎样得出可靠的结论

1. 同一场景、只改一个变量，各出 2 条以上再比较（每次生成本来就不一样）。
2. 结论写清楚证据是「单例」还是「多例」，有没有反例。
3. 推翻旧规则时，把旧规则留在表里，写明为什么被推翻。
